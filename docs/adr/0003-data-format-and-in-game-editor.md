# 场景采用声明式数据格式 + 游戏内可视化编辑器；反 DSL

场景以**声明式 JSON 数据**（场景数据 DTO）定义与分发，配**游戏内可视化编辑器**（在场景中摆放 / 录制动作 / 写文案并导出，支持热重载，作者零代码）。步骤类型为**封闭枚举**，并提供注册 Java `StepType` 的扩展点；**禁止**表达式、条件、循环、用户函数与算术（除字面量参数）——格式不得退化为编程语言。手作与自动场景按**场景粒度**覆盖 / 扩展（`include`、按 `stepId` 的 `skip`），不做步骤级字段合并。

**Status**: accepted

**Considered Options**:

- **数据格式 + 编辑器（选定）**：社区可写、可热重载、与自动生成同构。
- 仅数据格式（编辑器后补）：见效快，但作者门槛高、产出慢。
- Java 代码定义（Ponder 原做法）：最灵活，但无法社区化。

**Consequences**:

- 编辑器与运行时**共用同一 DTO**（单一事实源），避免模型漂移。
- 需要格式版本迁移与 schema 白名单测试（拒绝未知节点形状）。
- 编辑器须**门控**（仅作者 / 开发），并提供"导出自动场景为草稿"入口。
